## 요구사항

### Component (컴포넌트)

- UI를 나누는 작은 단위
- 각각의 Component는 자신만의 로직과 렌더링을 담당
- 반드시 **함수형 컴포넌트**로 구현

**구현 방식**

- 함수형 컴포넌트를 감싸는 `FunctionComponent` 클래스를 직접 만듦
- 이 클래스에는 아래 기능이 필요:
  - `hooks` 배열 (상태 저장용)
  - `mount()`: 처음 렌더링
  - `update()`: 상태 변경 후 다시 렌더링

**제약조건 (중요)**

- Hook은 최상위 컴포넌트에서만 사용 가능
- State(상태)는 "최상위 컴포넌트(루트 컴포넌트)"에서만 관리
- 자식 컴포넌트는 state를 가지지 않고, 부모로부터 전달받은 `props`만 사용 (**Lifting State Up** 패턴)
  - 자식 컴포넌트는 Stateless, props만 받아서 사용하는 순수 함수로 구현

---

### State (상태)

- 값이 변경될 수 있는 동적 데이터
- State가 바뀌면 → 화면이 자동으로 다시 그려져야 함

---

### Hooks

함수형 컴포넌트에서도 상태와 생명주기를 사용할 수 있게 해주는 기능

**최소 구현 대상**

- `useState`
- `useEffect`
- `useMemo`

> 핵심 질문: "함수는 매번 새로 실행되는데, 상태는 어떻게 유지할까?"
> → 이 문제를 해결하는 것이 Hooks의 핵심

### Virtual DOM + Diff + Patch

- Week 3에서 만든 Virtual DOM을 활용

**동작 흐름**

1. Virtual DOM 생성
2. 이전 Virtual DOM과 비교 (Diff)
